# AI Native Learning OS 学习执行规则 V0.1

> V3.0 基线说明：本规则继续作为 Learning OS 的运行协议；战略方向、S1～S7 阶段依赖、统一成长树实践和阶段门禁以 `content/plans/AI_Native_系统学习与统一成长树实践路线_V3.0.md` 为准。正文中的“六个月”旧称仅表示原有 Goal → 月 → 周 → 日层级，不构成独立战略总纲。

> 本文件是个人 AI Native Learning OS 的统一学习执行协议。
>
> 它从 S1 执行计划、Learning OS 运行模型和既有运行经验中提取稳定规则，使后续阶段、任务、成果和界面使用同一套“开始—执行—验证—沉淀—复盘”标准。

---

## 一、协议定位

### 1. 它负责什么

本协议统一回答：

- 一个任务怎样进入正式执行队列。
- 一次学习会话按什么顺序运行。
- 什么时候需要闭卷，什么时候可以查资料。
- AI 能参与什么，不能代替什么。
- 学习总结、成果和证据怎样区分。
- 任务状态怎样更新。
- 失败、中断和门禁未通过时怎样处理。
- 日、周、月复盘怎样改变计划。

### 2. 它不负责什么

- 不决定六个月学习方向。
- 不替代阶段执行计划和配套学习资源文档。
- 不规定所有任务必须填写相同长度的表格。
- 不把知识地图变成学习顺序。
- 不追求一次性改写所有历史文件。

### 3. 规则优先级

| 标记 | 含义 | 执行方式 |
|---|---|---|
| 必须 | 关系到证据可信、状态正确或依赖安全 | 不满足就不能标记完成 |
| 条件性 | 只在闭卷、测试、真实数据、高风险动作等场景触发 | 触发后按必须规则执行 |
| 建议 | 用于提高效率和一致性 | 可根据任务特点简化，但要保留目标和证据 |

## 二、九条总原则

1. **目标驱动**：学习任务必须能追溯到月度里程碑和六个月能力目标。
2. **结果先行**：开始前先写清今天结束时必须留下什么，不以“阅读某篇文章”作为最终结果。
3. **先独立、后输入**：首次接触、测试和复习场景先保留自己的真实答案，再使用资料或 AI 校正。
4. **一次一件事**：一个学习会话只保留一个主要结果和一个主要差距。
5. **资源服务成果**：只读足以改变当天成果的指定范围，达到产出条件就停止。
6. **成果落盘**：正式结果必须保存到 Markdown 或项目文件中，只存在聊天记录里不算完成。
7. **证据决定状态**：阅读、讨论和长总结不能自动证明能力形成。
8. **反馈只改一点**：每轮反馈只选择一个最影响目标的问题进行修改。
9. **历史不可抹平**：首次独立作答、反馈修订和正式验证承担不同证据角色；可以保存在同一文档的不同区块或版本中，但不得覆盖原始证据。

## 三、任务进入执行队列的规则

### T-01：必须能追溯到上层目标

正式任务至少关联：

```text
六个月目标 → 月度里程碑 → 周阶段 → 每日/专项任务
```

无法追溯的临时任务必须说明加入原因、预期价值和替代了什么，否则不进入正式队列。

### T-02：必须有一个主要结果

任务开始前必须写清：

- 本次结束时必须看见的主要结果。
- 主要成果文件路径。
- 最低完成标准。

可以有多个支持材料，但只能有一个主要学习结果。

### T-03：必须检查依赖与门禁

- 前置任务未完成时，后续任务保持“未开始”。
- 门禁未通过时，只插入同类补强任务，不跳到更复杂主题。
- 答案、旧版本或参考图属于受控材料时，必须检查开放条件。

### T-04：必须设置时间盒

- 普通学习会话默认 60—90 分钟。
- 补强任务默认 20—30 分钟，最长不超过 45 分钟。
- 超过时间仍未完成时保存当前版本并记录卡点，不无限扩展阅读。

### T-05：建议先选择最小机制

任务、练习和项目设计都按以下复杂度逐级升级：

```text
确定性规则/程序
→ 单次/少量模型
→ 固定 Workflow
→ 动态 Workflow
→ 受控 Agent
```

这只是比较候选复杂度的操作顺序，不是所有任务必须逐级经过的成熟度阶梯。只有更简单机制无法满足同一目标、质量和风险约束，并且新增复杂度有可验证价值时，才升级；多 Agent 属于后续实现模式，不作为 S1 的第六种控制结构。

## 四、一次学习会话的标准流程

### E-01：定位

开始前必须确认：

- 当前任务 ID 和状态。
- 承接的月度能力与周阶段。
- 前置任务或门禁。
- 本次最小结果和主要成果路径。

### E-02：首次独立作答

首次接触日的独立作答用于记录真实起点，允许空白和错误；正式考核、复习日和迁移日的无资料作答用于验证独立掌握。独立作答是执行条件，不是独立文件类型。

以下情况必须先独立完成：

- 起点认知图或首次定义。
- 首测与复测。
- 不看上一版本的独立重写。
- 不看资料的地图与讲解。
- 陌生场景迁移。

### E-03：只读指定输入

读取资源时必须遵守：

- 格式中立：视频、课程、文章、标准和图示按目标匹配与单位时间收益选择，不按“官网优先”或“名师优先”。
- 角色分工：通常只选一个主讲资源建立理解，再用一个标准、官方规范或原始材料核验关键边界；案例与练习不能被讲解资源替代。
- 名师资源也必须给出精确片段、唯一用途、时间预算和文字替代；不得因讲师知名度通刷与当前阶段无关的长课。
- 只读与当天问题直接相关的小节。
- 记录 3—5 条能改变成果的结论，而不是复制长文。
- 达到成果条件后停止，不沿引用无限扩展。
- 厂商案例用于分析结构和决策，不把厂商效果表述当作独立事实。

练习要求的每个核心判断必须能够追溯到以下至少一种输入：前置成果、题面明确给定事实、当天指定资源、学习者真实任务事实。四者都没有提供时，合格答案是“信息不足 + 需要补充的约束/获取方式”，不得要求学习者猜测，也不得让 AI 虚构项目事实。

首测、复测、独立重写、独立地图和未见场景迁移属于有意封锁新输入的能力验证；它们的充分输入是此前已完成的判定标准、成果和题面本身。不得为了“帮助做题”提前开放参考答案、旧版本或密封评分说明。

### E-04：围绕四问理解

核心知识节点至少回答：

1. 它是什么？
2. 解决什么问题？
3. 什么时候使用或不使用？
4. 怎样证明它有效？

“什么时候使用”必须包括不适用条件和更简单替代；“怎样证明”必须落到可观察结果、指标、测试或反馈。

### E-05：必须有一次主动加工

一次正式学习任务至少包含一种主动行为：

- 案例拆解或反例分析。
- 不看资料解释或重画。
- 分类判断或专项练习。
- 架构设计或最小实验。
- 真实任务应用。
- 测试、Eval 或迁移题。

单纯阅读和摘录不构成完整学习会话。

### E-06：写入指定成果

- 主要结果写入任务指定的主要成果文件。
- 每日练习、总结和完成检查写在同一主文档，不另建支持成果；正式阶段考核仍使用专用证据文档。
- 结论必须用自己的话，并能区分来源事实、个人判断和待验证假设。

### E-07：按标准自检

自检只检查当天资源和任务明确要求的范围，不提前要求后续综合能力。每日自检是轻量完成检查，不等同于正式考核，也不要求对当天涉及的每个知识点逐一取证。

自检必须给出：

- 通过或未通过。
- 对应的具体标准。
- 一个最大差距。

正式能力验证集中放在阶段门禁文档；首测、复测、独立讲解和迁移日练是形成性证据。每日成果通过只表示当日任务可以继续推进，不能直接把知识节点标记为“已验证”。

### E-08：只修一个问题

当成果未通过时，选择一个对目标影响最大的问题修正。除非门禁明确要求，不同时扩写多个主题。

### E-09：收尾并确定续接点

结束时至少记录：

1. 完成的任务和结果。
2. 新增成果或证据路径。
3. 通过/未通过的标准。
4. 一个未解决问题。
5. 当前状态是否变化。
6. 下一次从哪里继续。

## 五、独立作答、测试与受控材料规则

### C-01：受控材料必须后开

| 场景 | 完成前禁止查看 | 开放条件 |
|---|---|---|
| 首测 | 参考答案、他人完整答案 | 全部题目和理由完成 |
| 复测 | 复测参考答案、首测对应答案模式 | 全部新题完成 |
| 独立重写 | 自己的上一版本 | 首次独立区块完成并保留 |
| 独立地图/讲解 | 旧地图、案例、总结、资料 | 首次地图和讲解结束并保留 |
| 迁移测试 | 判定标准、相似例题、答案 | 所有新场景完成 |

### C-02：首次独立证据必须保留原貌

- 首次独立版本允许错误，不能事后直接改成完美答案。
- 校正内容应进入同一文档的校正区、明确修改记录或版本历史；不要求另建开卷版/闭卷版文件。
- 需要比较前后变化时，必须保留首版与反馈版。

### C-03：评分不能只看答案字母

机制判断、架构选择和开放问题至少同时评估：

- 结论是否合理。
- 理由是否说明控制权、边界或权衡。
- 风险与失效条件是否被识别。
- 是否能说明何时改用另一机制。

### C-04：正式考核按关键节点设置

- 不为每个学习日、每个概念或每个成果重复安排正式考核。
- 一组相关知识完成后，使用综合题、闭卷讲解、迁移场景或真实任务统一验证。
- 阶段考核优先检查关键能力和高风险边界，不追求覆盖所有资料细节。
- 需要验证保持程度时安排延迟复测，不用当天重复作答冒充长期掌握。

正式考核还必须满足以下效度底线：

- 使用带行为描述的评分锚点，说明 0、1、2 分或通过/不通过分别代表什么，不只给总分。
- 核心能力和严重风险项使用不可补偿门槛；总分再高也不能抵消核心维度缺失、越权或高风险不可逆误判。
- 迁移考核优先使用至少两个形成关键约束对照的未见场景，避免一个样本偶然命中。
- AI 或评分者生成的正式题目须在学习者作答前保存题面与评分口径；题面质量由独立角色检查，评分时按预注册口径处理缺陷，不迎合答案改题。
- 阶段门禁的关键主观维度必须由第二评分者盲审抽查并记录分歧；缺少要求的独立复核时，结论保持 `PARTIAL`。

### C-05：补充练习由稳定弱点触发

以下情况触发专项补练：

- 同类错误在不同题目、任务或场景中重复出现。
- 同一判断规则经过反馈后仍无法迁移到新场景。
- 错误涉及核心概念边界、身份权限、安全治理或不可逆动作，即使首次出现也可能造成严重后果。

一次偶发的表达疏漏或非关键细节错误可以记录，但不自动增加新的正式任务。补练一次只处理一个主要弱点，并使用新题或新场景复测。

## 六、AI 协作规则

### AI-01：AI 不能代替首次独立版本

以下内容必须由学习者先完成：闭卷回答、首测、复测、首次任务判断、真实任务首版和迁移题。

### AI-02：每轮只请求一个具体反馈

有效请求应包含：

- 要检查的成果或片段。
- 明确标准。
- 只指出一个最重要缺口。
- 说明为什么是缺口。
- 指向应核对的证据或资料。
- 不代替学习者重写完整答案。

### AI-03：反馈必须可行动

以下反馈不合格：

- 只说“很好”或“不够好”。
- 一次给出大量修改点。
- 没有说明哪里不好和为什么。
- 没有对应目标、标准或证据。
- 直接生成完整答案，破坏闭卷证据。

### AI-04：最终判断由学习者负责

学习者负责目标、优先级、真实决策、证据可信度和计划调整；AI 负责提高解释、质疑、练习设计、评估和组织效率。

## 七、成果、证据与版本规则

### A-01：区分四种内容角色

| 角色 | 回答的问题 | 示例 |
|---|---|---|
| 任务 | 今天要做什么 | D2 完成 8 个适用性判断 |
| 会话记录 | 实际怎样学、哪里卡住 | D2 每日学习总结 |
| 成果 | 学习形成了什么可复用输出 | 任务适用性判断表、案例拆解、任务说明 |
| 证据 | 什么证明能力已经形成 | 闭卷、测试、迁移、Eval、用户反馈 |

同一文件可以同时承担成果和证据，但必须明确主要角色和证明对象。

### A-02：主要成果与支持成果不能混淆

- 任务指定文件是主要成果。
- 总结、聊天记录和资料摘录通常是支持成果。
- 支持成果再完整，也不能自动替代主要成果的通过条件。

### A-02A：一任务一主提交件

- 每个正式日任务只能指定一个当天主提交件；过程记录、题目记录、讲解记录和后续计划可以作为支撑件。
- 已有专业成果文件能承载当天结果时，直接把它作为主提交件，不另建“每日完成总结”。
- 执行计划必须提供主提交件的可点击入口；多文件任务必须明确“主提交件 / 支撑件”。
- 主提交件至少包含：任务身份、今日必须回答、专业成果正文、提交前验收、提交结论。
- “提交结论”只记录成果自检结果和最大差距，不是权威任务状态；任务 checkbox 与状态仍只在阶段执行计划维护。

### A-03：证据必须可追溯

证据至少指明：

- 证明哪项能力或知识节点。
- 使用什么标准验证。
- 结果是什么。
- 证据文件在哪里。
- 是独立完成、AI 反馈后完成，还是外部真实反馈。

### A-04：版本承担不同证据职责

- V0.1 通常记录起点或首次独立版本。
- 闭卷版记录脱离资料的真实能力。
- V0.2/V0.3 记录基于指定证据的修订。
- V1.0 表示达到当前阶段可交付标准，不代表永久最终版本。

不得用新版本覆盖起点、闭卷或首测版本。

### A-05：事实、判断与假设要可区分

正式成果应尽量区分：

- 来源明确支持的事实。
- 学习者基于证据作出的判断。
- 尚待验证的假设或问题。

## 八、状态与门禁规则

### S-01：统一状态

| 状态 | 定义 | 是否解锁下一任务 |
|---|---|---|
| 未开始 | 尚未进入，或依赖未满足 | 否 |
| 学习中 | 已开始，但主要成果未达到标准 | 否 |
| 待验收 | 主要成果已形成，尚未完成自检 | 否 |
| 已完成 | 主要成果达到当天标准 | 是，除非还有阶段门禁 |
| 已验证 | 被后续独立证据再次证明 | 是 |
| 阻塞 | 缺资源、数据、权限或连续失败 | 否，先处理阻塞 |
| 已归档 | 已被明确版本替代，仅保留历史 | 不适用 |

### S-02：完成状态必须有依据

“已完成”必须同时满足：

1. 主要成果文件存在且已填写。
2. 当天通过标准已自检。
3. 受控材料没有提前开放。
4. 没有用 AI 完整生成冒充独立成果。
5. 状态可以指向成果或证据路径。

### S-03：任务完成与能力掌握分开

```text
任务已完成
→ 后续测试/闭卷/迁移
→ 能力已验证
```

一次任务完成最多证明当前任务达标；只有后续证据才能提升节点能力状态。

### S-04：门禁优先于日历

- 周门禁未通过，不因日期到期自动进入下一阶段。
- 月度验收未通过，不把全部内容机械重学；把最大缺口转成下月第一个小练习。
- 计划可以顺延，证据环节不能为了追进度取消。

## 九、中断、困难和失败处理

### F-01：资源读不动

按顺序降级：

1. 使用计划指定的入门课程或短视频。
2. 只读标题、开头、图和结论，写 3 条确定结论、2 个问号。
3. 页面不可访问时使用同日列出的替代官方来源。
4. 仍无法完成时记录具体卡点，不改变当天主要成果。

### F-02：错过学习日

- 顺延任务，不在第二天做双倍任务。
- 每完成五个学习日可以设置一个 30—45 分钟缓冲日。
- 缓冲日只补文件落点、证据链接或一个未通过项，不增加新知识。

### F-03：连续未通过

- 连续两次未通过同类任务，或阶段考核显示同类错误在不同场景稳定出现时，把练习缩小一半。
- 只练错误最集中的一个边界。
- 不扩大资料范围，不同时修多个问题。

### F-04：数据、权限或风险不成立

真实任务遇到以下情况必须停止或换题：

- 没有合法可用的数据。
- 风险不可控或需要未经授权的操作。
- 不可逆动作没有人工确认点。
- 无法在当前阶段用样例验证关键假设。

不能用假设性描述冒充真实验证。

## 十、日、周、月复盘规则

### R-01：日复盘只为无摩擦续接

最小输出：今日结果、成果/证据路径、一个未解决问题、当前状态、下一动作。

若当天主提交件已经包含提交结论与下一动作，日复盘直接复用该部分，不重复创建日总结。

### R-02：周复盘检查能力推进

每周检查：

- 任务完成是否有成果支持。
- 成果是否真的证明本周能力。
- 哪些节点只停留在 L1/L2。
- 哪些任务耗时高但价值低。
- 下周继续、停止或调整什么。

周复盘只选择一个最大差距和一个计划调整。

### R-03：月度验收是能力评估

月度验收必须检查：

- 目标能力是否达到要求等级。
- 知识是否形成关系，而非术语列表。
- 实践或项目里程碑是否完成。
- 是否存在独立可复查证据。
- 是否能综合讲解并迁移。
- 下月第一项练习是否由证据产生。

月度验收不是每日笔记汇总。

## 十一、Markdown 与元数据规则

### D-01：权威数据关系

```text
Markdown / 项目文件 = 内容与证据
Git = 历史与差异
Learning OS 界面 = 读取、执行、关联和展示
浏览器本地存储 = 临时草稿与界面状态
```

### D-02：新增关键文件使用最小元数据

建议字段：

```yaml
id: unique-id
title: 文件标题
type: plan | task | session | node | artifact | evidence | review | guide
status: draft | active | not_started | learning | review_pending | completed | verified | blocked | archived
created: YYYY-MM-DD
updated: YYYY-MM-DD
goal: 对应目标
milestone: 对应里程碑
week: 对应周阶段
tasks:
  - 关联任务 ID
nodes:
  - 关联知识节点 ID
evidence_for:
  - 被证明的能力
sources:
  - 外部资料或内部文件
```

字段按角色选用，不要求每个文件填满所有字段，也不一次性重写旧文件。

### D-03：状态不从文件是否存在推断

空模板存在不代表任务开始；长总结存在不代表指定成果完成；界面必须读取明确状态和证据关系。

## 十二、Obsidian Tasks 与每日执行治理

### OBS-01：单一权威任务源

每个阶段的任务定义、任务 checkbox 和任务状态只能存在于阶段执行计划中。其他文件不得复制任务定义或建立第二套任务状态。

```text
阶段执行计划 = 任务定义 + 权威 checkbox
     ↓
Obsidian Tasks = 读取 + 查询
     ↓
执行看板 = 查询投影
     ↓
每日唯一练习文件 = 执行记录 + 实际产出
     ↓
证据文件 = 能力验证
```

### OBS-02：任务 checkbox 规则

- 正式任务（S1-Dxx）的 checkbox 只能出现在阶段执行计划中。
- 一个任务只能有一个权威 checkbox。
- 勾选 checkbox 表示任务执行达到通过标准，不等于能力已验证。
- 任务完成后移除 `#ai-native/current`，下一任务添加 `#ai-native/current`。

### OBS-03：时间语义区分

| 字段 | 含义 | 使用场景 |
|---|---|---|
| Scheduled | 计划执行日期 | 普通学习任务 |
| Due | 真实截止日期 | 仅外部硬截止日期 |
| Reminder | 开始提醒 | 仅当前任务 |

普通 S1 学习任务默认不设 Due Date。不得把计划日期全部转换成 Due。

### OBS-04：执行看板职责

执行看板只做查询投影，不存储任务定义、任务状态或复选框。

看板可以显示：
- 当前任务（#ai-native/current）
- 今日计划（scheduled today）
- 已计划未完成
- 最近完成

看板不得存储：
- 任务权威 checkbox
- 任务状态
- 完整任务定义
- 通过标准
- Reminder 副本

### OBS-05：每日唯一练习文档与可选学习笔记

每日唯一练习文档记录任务要求的成果、轻量检查和续接点，是当天唯一主提交件。观看视频或阅读文档时产生的扩展理解、感悟、疑问和认知变化，可以在 `content/sessions/` 单独记录为可选学习笔记。

每日练习文档可以记录：
- 实际执行过程
- 首次独立版本
- 实际成果路径
- 自检结果
- 最大差距
- 下一续接点
- 日收尾信息（已合并）

每日练习文档不得成为：
- 任务 checkbox 权威源
- 任务状态权威源
- Scheduled/Due/Reminder 存储
- 能力验证最终状态

Session 只记录学习过程，不得成为：

- 第二份任务提交件
- 任务 checkbox 或任务状态权威源
- 未经核验的长期知识资产
- 练习、迁移题或正式考核的替代物

### OBS-06：模板职责边界

| 模板 | 职责 | 限制 |
|---|---|---|
| 每日任务卡 | 仅限临时/补强任务 | 已定义的 S1-Dxx 不得使用 |
| 学习过程笔记 | 可选记录资料理解、感悟、疑问和认知变化 | 不替代主练习、不维护任务状态、不自动成为知识资产 |
| 日收尾 | 已废弃 | 已合并到每日唯一练习文档 |
| 补强任务卡 | 门禁/测试触发的短时补强 | 不替代正式任务 |

## 十三、协议实施边界

### V0.1 立即适用

- 第一个月 D2 之后的学习任务。
- 后续新增任务、会话、成果、证据和复盘文件。
- Learning OS 界面未来的数据字段设计。

### V0.1 暂不要求

- 批量改写 D1—D20 已有专用模板。
- 为每个旧文件补齐全部 frontmatter。
- 建立后端、数据库或自动状态同步。
- 将所有任务强制套进一个巨大表格。

### 升级条件

完成 D2、D3、D4 三种不同任务后，检查：

1. 规则是否导致重复填写。
2. 模板是否能明确主要成果与支持成果。
3. 闭卷和开放控制是否清楚。
4. 状态是否能由证据判断。
5. 下一任务是否可以无摩擦续接。

只有实际运行发现结构性问题时才升级 V0.2。

## 十四、一页执行检查清单

### 开始前

- [ ] 任务能追溯到月度目标。
- [ ] 前置任务和门禁已经满足。
- [ ] 已写清唯一主要结果、成果路径和完成标准。
- [ ] 已确认哪些材料在完成前不能打开。

### 执行中

- [ ] 需要闭卷时先保留独立版本。
- [ ] 只读指定范围并提取能改变成果的结论。
- [ ] 至少完成一次主动加工。
- [ ] 结果写入指定 Markdown 或项目文件。
- [ ] AI 每轮只反馈一个具体问题。

### 结束时

- [ ] 按明确标准判断通过或未通过。
- [ ] 只记录一个最大差距。
- [ ] 状态有成果或证据路径支持。
- [ ] 已确定下一次续接点。
