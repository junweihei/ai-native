# AI Native Learning OS 统一模板规范 V0.1

> 本文件定义模板的共同字段、组合方式和使用约束；每天可直接复制的独立模板位于 `00-templates/`，并由模板注册表统一映射。
>
> “统一”不是让所有学习都填同一张大表，而是让不同文件共享同一套 ID、目标、成果、证据、状态和续接关系。

---

## 一、模板体系

### 1. 四类核心模板

| 模板 | 对象 | 回答的问题 | 什么时候创建 |
|---|---|---|---|
| A. 任务卡 | Task | 要做什么、为什么、怎样完成 | 计划任务进入正式队列时 |
| B. 学习会话记录 | Session | 这一次实际怎样学、形成了什么变化 | 每次真实学习会话结束时 |
| C. 成果与证据记录 | Artifact / Evidence | 产生了什么、证明什么、怎样验证 | 有正式交付物、闭卷、测试或反馈时 |
| D. 复盘记录 | Review | 证据说明什么、下一步怎样调整 | 日收尾、周门禁或月度验收时 |

知识节点四问作为 B 模板的标准理解模块；需要长期复用时，再使用“知识节点卡扩展模板”。

### 2. 不需要每次全部使用

| 学习活动 | 必用 | 按需使用 | 保留现有专用表 |
|---|---|---|---|
| 概念/知识节点学习 | A + B | 节点卡扩展、C | `00-templates/02-learning/知识节点学习模板.md` 是统一入口 |
| 案例拆解 | A + B | C | D6—D10 的案例模板 |
| 首测、复测、专项练习 | A + B + C | D | 练习与答题专用文件 |
| 真实任务应用 | A + B + C | D | V0.1/V0.2/V1.0 专用文件 |
| 周门禁/月度验收 | D | C | 现有周/月复盘文件 |

同一个现有文件已经包含某些字段时，不重复创建新文件。只补缺失的目标、状态、证据或续接关系。

## 二、共同字段与命名规则

### 1. ID 规则

```text
目标：G6M
月度里程碑：M01、M02……
周阶段：M01-W01、M01-W02……
每日任务：M01-D01、M01-D02……
补强任务：M01-R01、M01-R02……
学习会话：S-YYYYMMDD-01
知识节点：KN-英文短名
成果：ART-YYYYMMDD-短名
证据：EVD-YYYYMMDD-短名
复盘：REV-YYYYMMDD-类型
```

ID 用于关系和界面读取；文件名继续使用对学习者友好的中文名称。

### 2. 统一状态

| 中文显示 | frontmatter 值 | 使用条件 |
|---|---|---|
| 草稿 | draft | 文件结构已建立，尚未进入执行 |
| 生效中 | active | 计划、指南或协议当前生效；不用于表示每日任务完成度 |
| 未开始 | not_started | 任务存在，尚未开始或依赖未满足 |
| 学习中 | learning | 已开始，但主要成果尚未达标 |
| 待验收 | review_pending | 主要成果已形成，尚未完成自检 |
| 已完成 | completed | 达到当天任务标准 |
| 已验证 | verified | 被独立证据再次证明 |
| 阻塞 | blocked | 缺资源、数据、权限或连续失败 |
| 已归档 | archived | 已被正式版本替代，只保留历史 |

### 3. 通用最小元数据

不是所有字段都适用于每类文件；按模板保留必要字段即可。

~~~~markdown
---
id: unique-id
title: 文件标题
type: task | session | node | artifact | evidence | review
status: draft | not_started | learning | review_pending | completed | verified | blocked | archived
created: YYYY-MM-DD
updated: YYYY-MM-DD
goal: G6M
milestone: M01
week: M01-W01
tasks:
  - M01-D02
nodes:
  - KN-task-fit
evidence_for:
  - M01-C02
sources:
  - R1
  - R2
---
~~~~

### 4. 字段填写原则

- `id` 在创建后不变化。
- `status` 描述当前文件或对象的状态，不描述主观感觉。
- `tasks` 允许一个成果关联多个任务，但必须有一个主要任务。
- `nodes` 只放本次真正处理的核心节点，不把整张知识地图全部列入。
- `evidence_for` 只有在文件确实承担证据职责时填写。
- `sources` 可以使用资源编号，也可以使用内部文件路径。

## 三、模板 A：每日或专项任务卡

### 使用目的

任务卡属于计划系统，负责定义“应该做什么”，不记录长篇学习内容。第一个月已有 D1—D20 运行映射时，不需要为每一天重新创建任务卡；后续新增任务或补强任务使用本模板。

### 可复制模板

~~~~markdown
id: M01-DXX
title: 任务标题
type: task
status: not_started

updated: YYYY-MM-DD

  - M01-CXX

  - R__
~~~~

### 最小版本

临时小任务只需要六项：任务 ID、唯一结果、依赖、资源、成果路径、完成标准。

## 四、模板 B：学习会话记录

### 使用目的

会话记录属于学习执行系统，记录实际发生的学习过程。它不能替代专用成果表，也不要求每天写成长文。

### 默认最小模板

~~~~markdown
---
id: S-YYYYMMDD-01
title: {日期} {任务 ID} 学习会话
type: session
status: learning
created: YYYY-MM-DD
updated: YYYY-MM-DD
goal: G6M
milestone: M01
week: M01-WXX
tasks:
  - M01-DXX
nodes:
  - KN-____
sources:
  - R__
produces:
  - path/to/result.md
---

# {日期} {任务 ID} 学习会话

1. 我正在学习：____
2. 今天需要得到的结果是：____
3. 我闭卷先写出的判断是：____
4. 从指定资源确认的 3 个结论是：
   - ____
   - ____
   - ____
5. 我独立完成的成果或证据在：`____`
6. 当前最大的一个差距是：____
7. 下一次只继续或改进：____

## 状态收尾

- 本次结果：通过 / 未通过 / 阻塞
- 任务新状态：learning / review_pending / completed / blocked
- 判断依据：____
- 实际用时：____ 分钟
~~~~

### 四问理解模块

学习核心知识节点时，把下面模块插入会话记录；普通测试或复盘不需要填写。

~~~~markdown
## 知识节点四问：{节点名称}

### 1. 它是什么？

- 一句话定义：____
- 它属于：执行范式 / 设计模式 / 组件 / 控制机制 / 处理阶段 / 模型任务 / 协议 / 横向保障 / 其他
- 与最容易混淆概念的边界：____

### 2. 它解决什么问题？

- 没有它会出现：____
- 它的核心价值：____
- 它不负责：____

### 3. 什么时候使用或不使用？

- 适用条件：____
- 不适用条件：____
- 更简单替代：____
- 主要代价和风险：____

### 4. 怎样证明它有效？

- 成功标准：____
- 可观察证据或指标：____
- 最小测试或对照：____
- 失败条件和停止规则：____
~~~~

### 什么时候升级为独立知识节点卡

满足以下任一条件时，使用 `00-templates/02-learning/知识节点学习模板.md` 建立独立卡片：

- 节点会跨多个月份重复使用。
- 节点与多个相邻概念存在重要边界。
- 节点需要单独的指标、实验或真实任务证据。
- 当前理解要进入知识地图长期维护。

### 轻量证据声明

专用文件已经有完整正文时，只需补充：

~~~~markdown
## 证据声明

- 对应任务：M01-DXX
- 主要证明：M01-CXX / KN-____
- 验证标准：____
- 结果：通过 / 待改进 / 失败
~~~~

### 版本关系字段

| 版本角色 | 状态建议 | 处理规则 |
|---|---|---|
| 起点/首次独立版 | completed | 永久保留，不被覆盖 |
| 闭卷版 | completed 或 verified | 校正进入另一版本 |
| 反馈修订版 | completed | 必须指向上一版本和修改依据 |
| 阶段交付版 V1.0 | verified | 达到当前门禁，不表示永久最终 |

## 七、常见任务怎样组合模板

### 1. 知识节点任务

```text
A 任务卡
→ B 会话记录 + 四问模块
→ 必要时升级为独立节点卡
→ C 轻量证据声明
→ 日收尾
```

### 2. 案例拆解任务

```text
A 任务卡
→ B 会话记录
→ 现有案例专用成果
→ C 轻量证据声明
→ 周复盘汇总跨案例规律
```

### 3. 测试与专项练习

```text
A 任务卡确认开放条件
→ B 记录独立执行过程
→ 现有答题/练习专用文件
→ C 记录分数、理由质量和弱点证据
→ D 决定下一补强任务
```

### 4. 真实任务应用

```text
A 任务卡
→ B 会话记录
→ C 保存 V0.1 / 闭卷 V0.2 / V1.0 版本与证据
→ D 月度验收决定是否进入主项目
```

## 八、D2—D4 适配验证

本节验证统一模板是否能承载三类不同任务，不替学习者填写实际答案。

| 验证项 | D2 适用性判断 | D3 机制边界 | D4 架构与三条流 | 结果 |
|---|---|---|---|---|
| 可追溯目标 | M01-C02 | M01-C02 | M01-C01 | 通过 |
| 唯一主要成果 | 8 个个人任务判断 | 四类机制边界草稿 | 六层和三条流草稿 | 通过 |
| 主要/支持成果可区分 | D2 判断表 / D2 总结 | D3 草稿 / D3 总结 | D4 草稿 / 会话记录 | 通过 |
| 闭卷开放条件清楚 | 先判断，后看 R2/总结 | 先定义与举例，后看 R3/总结 | 先理解官方组件，再归类；非纯闭卷 | 通过 |
| 四问是否强制 | 只按需，不要求完整节点卡 | 边界问题为主，按需 | 组件职责和有效性按需 | 通过 |
| 完成标准可观察 | 2/2/2 分布和理由 | 8 例、控制权和边界 | 归类理由、三条流起止 | 通过 |
| 状态可由证据判断 | 当前 learning | 当前 learning | not_started | 通过 |
| 下一任务可解锁 | 完成后 D3 | 完成后 D4 | 完成后 D5 | 通过 |

验证结论：四类核心模板可以覆盖 D2—D4，同时保留专用成果表；没有要求重复抄写每日资源或长总结。

## 九、模板使用约束

### 必须保留

- ID、上层目标、任务状态。
- 唯一主要结果、主要成果路径、完成标准。
- 需要时的闭卷和材料开放条件。
- 证据声明与下一续接点。

### 可以删减

- 不适用的 frontmatter 字段。
- 不涉及核心知识节点时的四问模块。
- 没有版本演进时的版本对比。
- 日收尾已经写入会话记录时的独立日复盘文件。

### 禁止做法

- 为了填满模板制造无意义内容。
- 同一结论在任务卡、会话、成果和复盘中重复四次。
- 用统一模板覆盖现有闭卷版、首版或参考答案。
- 因为模板字段很多而延迟真正的学习任务。

## 十、V0.1 落地方式

1. D2 继续填写现有 `content/knowledge/任务适用性判断_D2.md`，不新建重复任务卡。
2. D2 补链结束时，按 B 模板的最小收尾记录结果和下一步。
3. D3 使用现有边界草稿，并遵守先闭卷、后校正的开放规则。
4. D4 验证不同类型的架构任务是否仍可使用同一状态与证据语言。
5. 完成 D4 后复盘是否存在重复填写，再决定是否把稳定元数据加入专用文件。
6. 在 D2—D4 验证前，不批量改造已有 D1—D20 模板。
