## 一、阶段定位与核心问题

S1 = 整体认知与机制判断。核心问题是：面对一个真实任务，能否从业务结果出发，先选择最低充分的控制结构，再选择最小必要的能力组件，并用成果、边界、风险和证据说明判断。

S1 的目标深度是 **L1–L2：能解释、能判断、能迁移，不要求实现完整系统**。阶段完成时，面对一个此前未见的真实任务，应能在不看资料的情况下形成一页机制判断：写清用户结果和决定性约束，选择最低充分控制结构与最小必要组件，说明谁控制下一步、为什么不用更简单方案、风险与人工边界，以及什么新证据才支持升级复杂度。

```text
控制结构：确定性规则/程序、单次或少量模型、固定 Workflow、动态 Workflow、受控 Agent
能力组件：Context、Retrieval、Knowledge、Memory、Tool、External State、Human Approval
```

两条轴分开判断；组件可以服务不同控制结构，不能把出现 Tool、Context 或 Retrieval 自动等同于 Agent。

统一成长树是贯穿式真实 AI Native 实践主项目。S1 不重新选择一个“后续数月主项目”，而是从统一成长树中取一个适合机制判与最小验证的真实问题。

## 二、能力目标

- 能画：15 分钟不看资料画出五问、六层与三条流。
- 能判断：根据结果确定性、路径可预写性、中间证据和“谁控制下一步”选择控制结构，再按任务缺口选择能力组件。
- 能拆：从案例中识别模型之外的知识、工具、权限、评测、人工接管和反馈回路。
- 能做：从统一成长树选择一个真实问题，形成可验证的一页任务说明和 5 个验收样例。
- 能迁移：对至少 5 个未见场景分别选择控制结构和能力组件，说清简单替代、边界、风险和切换条件。
- 能保持：在约一周后的变式复测中仍达到同一门禁标准。
- 能迭代：根据证据优先选择一个主要弱点，转成 S2 前置练习。

## 三、不做范围

- 不开发完整产品，不提前实现统一成长树。
- 不选择固定框架、云平台、数据库或模型供应商。
- 不增加模型训练、微调、向量数据库实现、部署或多 Agent 编码。
- 不以阅读量、笔记量或日历时间作为能力完成标准。
- 不把聊天界面、RAG 或使用模型自动等同于 Agent。
- 不提前设计 S2–S7 的每日任务。

## 四、统一执行闭环

每次只运行一个闭环：

```text
先看结果
→ 首次独立作答
→ 按资源文档只读指定范围
→ 写入指定成果
→ 按标准自检
→ 优先修一个关键问题
→ 记录证据与续接点
```

60 分钟版：5 分钟定义结果，15 分钟首次独立作答，20 分钟读指定范围，15 分钟补正同一份成果，5 分钟自检。90 分钟版只增加 20 分钟案例/练习和 10 分钟独立复述。

首次接触日的独立作答用于记录起点，允许空白和错误；正式考核和复习日的无资料作答才验证独立掌握。读到足以完成结果就停止，不把通读长文当作完成。

### 日检、考核与补练分层

- **每日轻量自检**：只判断当天唯一成果是否达到任务明确标准，并记录一个最大差距；不要求每天对每个知识点做正式考核。
- **阶段性正式考核**：集中放在 P1、P2、P3 和 S1 Final 四份考核文档，用于验证能否脱离资料、区分边界、迁移和保持；日练中的首测、复测和讲解只提供练习证据。
- **补充练习触发**：同类错误在不同题目或场景中重复出现，说明形成稳定弱点；涉及核心边界、权限、安全或不可逆风险的严重错误，首次出现也可以立即触发补练。
- **补练范围**：一次只处理一个最影响阶段目标的弱点，完成后用新题或新场景复测；不把整个阶段机械重学。
- **长期沉淀**：只记录可迁移的判断规则、稳定错因、关键边界和经验证的方法；普通过程、资料摘录和已有定义不重复进入知识资产。

### 每日提交约定

- 每个 D01–D20 任务只有一个“当天主提交件”；点击计划中的链接即可开始填写。
- 每份日练都在同一文件中完成今日目标、指定资源、今日练习、练习总结和完成检查；不再拆分开卷版、闭卷版或第二份提交件。观看视频、阅读文档时形成的额外理解、感悟和疑问，可以另记到 `content/sessions/`，但 Session 只是可选学习笔记。
- 提交结论是成果自检，不是任务状态。只有按通过标准复核后，才在本计划更新唯一权威 checkbox 与状态。
- 已有专业成果能承载结果时不另建每日总结，避免同一结论重复填写。
- Session 不维护任务状态、不替代当天主提交件，也不因内容丰富而自动成为正式能力证据；值得长期复用的内容经核验后再提炼到 `content/knowledge/`。

### 学习—练习对齐约定

- 每个日练必须区分三种活动：**起点诊断**允许不会，**带支架练习**只能使用当日已教方法，**独立验证**只能检查前序已经练过的能力。
- “资源中出现过一个术语”不等于已经教会。只有资源明确提供操作定义、判断步骤或示例边界，并且日练给出对应练习位置，才能进入后续考核。
- 正式考核中的每个评分维度，必须能反向追溯到至少一次明确教学和一次带反馈练习；不能在未练习的情况下直接进入未见场景。
- 当天练习不得要求学习者自行发明课程未教的方法。真实任务事实缺失时写“信息不足 + 获取方式”，不能用通用资料或 AI 猜测补齐。
- 每日具体的“学习什么、怎样练习、提交什么、如何验收”统一以资源文档中的 D1–D20 学习—练习合同和本计划的执行步骤为准。

## 五、阶段结构

- **S1-P1 图**：D1–D5，建立全貌、机制边界和质量视角。
- **S1-P2 拆**：D6–D10，用三个复杂产品案例和一个简单方案对照形成初始假设；能稳定说明边界和所需验证证据后停止增加案例。
- **S1-P3 练**：D11–D15，专练机制判断并从统一成长树选择真实问题。
- **S1-P4 用—证—迭代**：D16–D20，形成任务说明、独立讲解证据、迁移证据和 S2 前置练习。

这些是能力执行段，不是自然周硬约束。S1 包含 20 个日练单元和 P1、P2、P3、Final 四次独立考核，至少按 24 次正式执行安排；Final 还需在 D19 后约 7 天执行延迟复测，因此不能承诺在 20 个连续自然日内完成。每 5 个日练后可安排一个缓冲/考核日；是否进入下一段由门禁决定。

### 建议执行节奏

| 执行段 | 正式执行顺序 | 进入下一段条件 | 建议缓冲 |
|---|---|---|---|
| P1 图 | D1 → D2 → D3 → D4 → D5 → P1 | P1 达到量规门槛 | D3 或 P1 后预留 1 次补证/补练 |
| P2 拆 | D6 → D7 → D8 → D9 → D10 → P2 | P2 达到量规门槛 | P2 后预留 1 次失败维度复核 |
| P3 练 | D11 → D12 → D13 → D14 → D15 → P3 | D14 达标且 P3 通过 | D12–D14 连续执行；P3 后预留 1 次复核 |
| P4 用—证—迭代 | D16 → D17 → D18 → D19 → D20 | S1 即时门禁达到 PASS 候选标准 | D17 或 D19 后预留 1 次整理/复核 |
| Final 保持性验证 | D19 约 7 天后生成并完成新变式题 | 同一量规达到门槛后转为 PASS | 允许在 D19 后 ±3 天执行 |

每次只安排一个日练或一次正式门禁；90–120 分钟任务可拆成同日两个专注时段，但不拆成两份提交。门禁未通过时只补失败维度并用新题复核，不按日历强行推进。

按标准首次执行计算，20 个日练约 25.25–26.5 小时，P1/P2/P3/Final 约 4.5–5.75 小时，基础正式投入约 29.75–32.25 小时；再预留约 4–8 小时用于阶段补练、证据整理和失败维度复核，通常落在约 33.75–40.25 小时。V3.0 的 35–45 小时是初始容量估算，不是必须凑满的学时；提前达到全部门禁即可停止，出现稳定弱点时则按证据使用预留时间。D3 当前已有知识学习，计划中的“补证 30–45 分钟”只用于当前运行快照，标准首次执行仍按 90 分钟估算。

## 十二、状态模型

| 状态 | 含义 | 进入条件 | 下一步 |
|---|---|---|---|
| not_started | 尚未进入正式执行 | 前置未完成或尚未排到 | 等待依赖 |
| learning | 已阅读、讨论或总结，但指定成果尚未通过 | 已开始输入或行动 | 完成指定成果并自检 |
| review_pending | 主要成果已形成，尚未按标准自检 | 成果文件非空且结构完整 | 只修一个问题 |
| completed | 主要成果存在并满足当天标准 | 成果、理由和自检齐全 | 进入下一任务 |
| verified | 已被段门禁、闭卷、复测、迁移或阶段门禁再次证明 | 后续独立证据支持 | 保留历史版本 |
| blocked | 缺资源、数据、权限，或连续两次未通过同类任务 | 已记录具体卡点 | 降级资源或缩小练习 |

```text
会话完成 ≠ 指定成果完成 ≠ 任务完成 ≠ 阶段能力形成
```

任务标记 completed 至少需要：指定成果已填写；是学习者自己的判断；当天通过条件已自检；若使用 AI 反馈，只修一个明确问题并保留首版或差异。会话总结是支持成果，不能替代指定成果。

## 十五、执行中断与降级规则

- 错过一次时直接顺延，不补双倍任务。
- 单次超过 90 分钟仍未完成：保存当前版本，记录一个卡点，状态保持 learning 或改为 blocked。
- 段门禁未通过：插入一个 20–30 分钟同类补强任务，只补最大差距，然后回到主线。
- 资源读不动：按配套学习资源文档的降级与停止规则处理，不无限增加文章。
- 数据、权限或风险条件不成立：立即停止该场景，缩小范围或按 D15 规则记录替换理由。
- 连续两次未通过同类任务：不继续堆资料，记录 blocked 和具体解除条件。

## 十六、AI 反馈使用规则

1. 必须先留下学习者首版，再请 AI 反馈。
2. 让 AI 优先指出一个最影响当天通过的问题，并引用当天标准；修复后仍未通过时再处理下一问题。
3. AI 可追问、挑战边界、检查证据和提示缺口，不得代写 D2/D3 能力证据。
4. 反馈若一次要求重写全文、增加未学概念或直接给闭卷答案，视为不合格。
5. 修改后记录“改了什么、为什么、哪条证据支持”，不用对话本身代替成果文件。
