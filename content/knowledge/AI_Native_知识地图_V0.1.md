# AI Native 知识地图 V0.1：起点认知图

日期：2026-08-24
学习阶段：D1，完成生成式 AI、LLM、Prompt、Agent 入门学习后

## 一、我现在怎样理解 AI Native

我目前认为：

> AI Native 是从设计软件开始，就把 AI 的理解、生成和辅助行动能力作为系统的一部分，让用户可以表达目标，而不只是按照固定菜单一步步操作。

它不只是“在原有系统里增加一个聊天框”，而是可能改变用户与软件交互、信息处理和任务执行的方式。

不过，我现在只形成了初步认识，还不能完整解释企业系统应该怎样落地。

**一句话定义：** AI Native = 以 AI 为基础能力，把软件从功能驱动重构为目标驱动。

**技术表达：** `Goal → Context → Model → Agent/Workflow → Tools → Systems → Feedback/Evals`

## 二、AI Native 试图解决什么问题

传统软件主要要求人适应系统：

```text
人理解业务问题
→ 人查找资料
→ 人判断下一步
→ 人进入多个系统操作
→ 人检查结果
```

我目前理解的 AI Native 是：

```text
人表达目标
→ AI 理解任务
→ AI 使用当前上下文和必要资料
→ AI 生成内容或辅助执行动作
→ 人检查结果
```

它可能解决的问题包括：

- 用户必须学习复杂的软件操作方式；
- 信息分散在文档和多个业务系统中；
- 很多任务需要理解自然语言，难以完全写成固定规则；
- 跨系统任务需要人反复查找、复制、判断和操作；
- 同类知识工作质量不稳定、耗时较长。

## 三、我目前认识的核心概念

### 1. 生成式 AI

生成式 AI 能根据输入和训练中学到的模式生成文字、图像、代码等新内容。

它生成的是符合上下文的结果，不代表结果一定正确。

### 2. LLM

LLM 是经过大量文本训练的大语言模型。

我目前把它理解为：

> LLM 提供自然语言理解和生成能力，是 AI 应用的重要能力来源，但 LLM 本身不等于完整的 Agent 或业务系统。

### 3. Prompt 和 Instructions

Prompt 是提供给模型的输入。

Instructions 用来说明：

- 要完成什么任务；
- 应遵守什么规则；
- 输出应采用什么格式；
- 哪些事情不能做。

### 4. Context

Context 是模型处理当前任务时能够看到的信息，包括：

- 用户当前的问题；
- 系统指令；
- 对话历史；
- 提供的文档内容；
- 工具返回的数据。

### 5. RAG

RAG 是先从外部资料中检索相关内容，再把内容放进 Context，让模型依据这些资料回答。

RAG 可以增加回答依据、降低无依据生成的风险，但不能保证回答一定正确。

### 6. Tools

Tools 是 AI 应用查询外部信息或执行现实操作的能力，例如：

- 查询数据库；
- 搜索文件；
- 调用业务接口；
- 创建工单；
- 发送通知。

### 7. Agent

我目前认为：

> Agent 是围绕一个目标组织模型、Instructions 和 Tools，并根据当前结果判断下一步的软件系统。

理解、推理和生成能力主要来自 Agent 使用的模型；Agent 还需要运行流程、工具权限、停止条件和人工控制。

## 四、我目前能画出的基本关系

```text
用户目标或问题
      ↓
Prompt / Instructions
      ↓
Agent 或 AI 应用
      ↓
使用 LLM 理解、判断和生成
      ↓
根据需要读取 Context、检索资料或调用 Tools
      ↓
生成内容或执行辅助动作
      ↓
用户检查结果
```

我现在能确认的一条关系是：

> Agent 不是独立于 LLM 的另一个“大脑”，而是围绕目标使用模型进行理解和生成，并在必要时组织工具完成任务。

## 五、我目前认识的技术组成

```text
AI Native
├── 模型能力
│   └── LLM
├── 当前信息
│   ├── Prompt
│   ├── Instructions
│   ├── Conversation History
│   └── Context
├── 外部知识
│   └── RAG
├── 外部行动
│   └── Tools
├── 任务执行
│   ├── Workflow
│   └── Agent
└── 结果控制
    ├── 人工确认
    ├── 安全与权限
    └── 效果评价
```

其中 Workflow、Agent、Memory、MCP、多 Agent 和完整评价体系，我还没有系统学会，暂时只保留位置。

## 六、我目前怎样判断结果好不好

我只能先使用几个简单标准：

- 任务是否完成；
- 结果是否与问题相关；
- 回答是否有资料依据；
- 是否执行了未经允许的操作；
- 用户是否还需要大量修改；
- 时间和成本是否能够接受。
