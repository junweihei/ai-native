# AI Native 知识节点注册表 V1.0

## 六层功能架构定义

六层是用于定位功能职责的架构视图；运行流描述信息、决策与反馈如何穿过这些层，横向保障则跨层生效，三者不是同一种树层级。

| 层         | 解决的问题                             |
| --------- | --------------------------------- |
| 业务/产品     | 明确用户目标、业务价值、成功标准和必须保留的人工控制。       |
| 模型应用      | 把模型的理解、生成、判断或规划能力转化为可验收的任务结果。     |
| 上下文/知识    | 为模型和流程提供足够、相关、可追溯且不过度暴露的任务上下文。    |
| 工作流/Agent | 控制步骤顺序、动态决策、工具选择、停止条件和人工接管点。      |
| 工具/集成     | 在明确权限与边界下连接数据读取、外部系统和可产生影响的动作。    |
| 工程/评测/治理  | 让系统可测试、可观察、可恢复，并持续管理安全、质量和生命周期风险。 |
本表把现有 D1—D4 成果、月度运行映射和 D18—D20 验收门禁整理为网站可读取的节点定义。它描述知识结构和证明规则，不表示学习者已经掌握，也不改变权威任务顺序。

## 状态说明

- 目标能力来自第 1 月计划，不代表当前能力已经达到。
- 当前能力只能由满足标准且独立性合格的证据支持；没有证据时必须显示“未评估”。
- 节点详情发现证据缺口时，只能返回本表列出的计划任务，不自动创建权威任务。
