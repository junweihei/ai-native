核心判断分三步：先根据下一步控制者、路径空间、子任务生成权、工具权限和停止条件选择最低充分控制结构；再选择最小必要能力组件；最后检查横向约束。

## 轴一：控制结构

| 控制结构 | 谁控制下一步 | 路径能否枚举 | 能否生成新子任务 | 工具权限 / 停止条件 | 适用条件与风险 |
|---|---|---|---|---|---|
| 确定性规则/程序 | 代码、公式、阈值或人工规则 | 完整枚举 | 否 | 写定 / 写定 | ____ |
| 单次/少量模型 | 调用方 | 调用流程可枚举 | 否 | 调用方控制 / 调用方停止 | ____ |
| 固定 Workflow | 预定义流程图 | 节点和分支可枚举 | 否 | 写定 / 写定 | ____ |
| 动态 Workflow | 受限编排器 | 具体路径运行时变化，任务类型和动作集合可枚举 | 只能组合许可类型 | 白名单 / 预定义终止规则 | ____ |
| 受控 Agent | 模型在目标内持续决策 | 具体路径和部分子任务不可预先枚举 | 是，但不得扩张目标或权限 | 白名单、预算、策略、审批 / 明确停止条件 | ____ |

## 快速判定问题

1. 结果能否由确定公式、阈值或条件完整描述？如果能，优先 ____。
2. 步骤是否固定，只是其中某一步需要理解或生成？如果是，优先 ____。
3. 是否只需一次或少量生成、抽取、分类、翻译或总结？如果是，优先 ____。
4. 系统是否只需在预定义边界内按中间证据选择分支？如果是，优先 ____。
5. 模型是否必须在受控边界内持续选择下一步和工具？如果是，才考虑 ____。
6. 是否需要生成设计时无法枚举的具体子任务；动作类型和权限是否仍受限：____。
7. 缺失信息来自 Context、Retrieval、Knowledge 还是 Memory：____。
8. 是否需要 Tool、External State 或 Human Approval：____。
9. Evaluation/Observability、Identity/Permission、Safety/Governance 是否成立：____。

## 过度设计快速检查

对每个场景额外回答：这个控制结构是不是比需要的更复杂？去掉某个能力组件后是否仍能满足结果与风险要求？若能，当前选择可能过度设计。
