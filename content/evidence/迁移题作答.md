## 测试完整性规则

1. 本文件在测试开始前不得包含正式场景正文。
2. 独立出题者或 AI 按 S1 学习资源文档的 D19 蓝图，在开始计时前一次性生成 5 题并写入下方“题目快照”。
3. 场景随机排序，不向学习者显示目标控制结构、答案或评分者提示。
4. 学习者提交全部答案后，评分者才填写评分、可接受答案范围和关键约束。
5. 即时测试和延迟复测不得复用表面故事；复测题须使用新领域或改变关键约束。

横向约束：Evaluation / Observability、Identity / Permission、Safety / Governance。

## 固定评分量规

每项只记 0 或 1 分。单题至少 4/5，且第 5 项必须为 1，才记为该题通过。

| 评分项 | 1 分条件 | 0 分条件 |
|---|---|---|
| 1. 控制结构及理由 | 选择能由题目约束支持，并说明谁控制下一步 | 只写名称、理由与约束冲突，或把组件当控制结构 |
| 2. 最小能力组件 | 组件逐项对应任务缺口，没有无理由堆叠 | 漏掉结果所必需组件，或把“可能有用”当作必要 |
| 3. 控制边界与升级条件 | 写清路径空间、子任务/工具权限、停止条件及何时升级 | 没有边界，或复杂度升级没有失败证据 |
| 4. 简单替代与五维比较 | 同约束比较质量、成本、延迟、可控性、可审计性并得出取舍 | 只说复杂方案更强，或未在同一约束下比较 |
| 5. 风险与审批 | 识别身份权限、敏感数据和高风险/不可逆动作的审批要求 | 允许未授权访问，或允许无人工确认执行高风险、不可逆动作 |

允许不同于评分者主导答案的控制结构，但必须由场景约束和上述量规支持。术语不同本身不得扣分。
