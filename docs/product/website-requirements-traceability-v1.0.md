1. 产品规格、设计系统、验收标准和 Learning OS 上位规则是否表达同一套产品。

3. 当前共识是否足以进入信息架构设计，以及哪些问题必须在后续阶段解决。

## 2. 状态口径

### 2.1 追踪状态

| 状态 | 含义 |
|---|---|
| 基线已定义 | 产品或设计文档已明确要求，可进入下一层设计 |
| 待 IA | 需要在信息架构阶段确定页面结构、进入/退出和信息排序 |
| 待线框 | 需要通过低保真线框验证布局、状态和任务流 |
| 未开始 | 尚未进入实现，符合当前阶段边界 |
| 未执行 | 尚无可运行产品，不应宣称验收通过 |
| 部分就绪 | 权威来源存在，但当前索引未完整结构化 |
| 缺失 | 当前权威数据或索引结构不能支持该需求 |

### 2.2 优先级

- **P0**：发布阻断闭环或数据安全要求，缺失时不得发布。
- **P1**：支撑计划理解、知识定位和证据回流；应在 V1 内完成。
- **P2**：历史查找和效率增强；可在 P0/P1 安全成立后完成。

### 5.3 已确认的关键数据风险

1. **受控材料泄露风险（Blocker for implementation）**：`20题首测_参考答案.md` 和 `10题复测_参考答案.md` 的答案摘要已经进入普通生成索引；未来搜索、预览或关联卡若直接使用当前索引，会在开放条件前泄露内容。
2. **任务不是一等对象**：D1—D20 的目标、时间、依赖、成果和通过证据主要存在于 Markdown 表格，构建器只按文件生成文档项，无法确定唯一当前任务。
3. **续接信息源存在但未投影**：运行映射 frontmatter 已有 `current_task`、`current_status`、`next_action`，当前索引未输出。
4. **关系图不足**：`artifact_id`、`template_id` 和 `nodes` 当前无有效填充，`evidence_for` 仅少量存在，无法支撑双向追溯。
5. **状态必须按对象解释**：D2/D3 的 session 文件状态为 `completed`，主要 artifact 状态为 `learning`。这不是数据冲突，而是“会话已完成、任务成果未完成”的合法情况；界面若按 `task_id` 粗暴合并状态会产生虚假完成。

这些风险不阻止信息架构设计，但在步骤 05“网站数据契约”完成前，不能进入依赖真实数据的产品实现。

## 8. 信息架构阶段的输入约束

下一阶段可以开始，但必须遵守以下约束：

1. 先设计发布阻断主路径，再设计路线图、知识地图和档案。
2. 一级导航使用五入口：今日、路线图、知识地图、学习档案、复盘。
3. 任务工作台和知识节点详情是上下文页面，不提升为平行一级入口。
4. 每个页面必须标出唯一主问题、唯一主行动、进入条件、退出去向和返回上下文。
5. P0 流程必须同时设计正常、部分数据、过期、错误、只读、阻塞和未保存恢复路径。
6. 受控材料在 IA 中采用“默认不可见正文”的安全模型，不使用当前索引摘要做示例。
7. 状态标签必须带对象语境，明确区分 task、session、artifact 和 evidence；L0—L4 独立展示。
8. 示例使用 M01-D01、D02/D03、D04 的真实关系，但不修改学习状态、不提前展示答案。
9. IA 只能定义产品行为和信息顺序，不假设框架、数据库、API 或部署方式。
10. IA 发现需要新增对象、字段或状态时先登记到 DEC 项，不直接更改内容契约。
