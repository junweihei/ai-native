## 1. 产品定义

AI Native Learning OS 网站是六个月个人学习计划的执行、记录、验证与复盘工作台。它把现有 Markdown 学习资产和计划关系投影成每天可执行的界面，但不建立第二套学习内容或状态。

> 产品北极星：让计划中的能力里程碑被可验证地完成。

网站不是课程平台、通用知识库、Markdown 文件浏览器或打卡应用。若界面只让文件更好看，却没有降低“确定下一步—形成成果—提交证据—继续学习”的摩擦，则不构成产品价值。

## 2. V1 目标与非目标

### 2.1 目标

V1 必须让学习者：

1. 打开网站后五秒内知道当前阶段、今日唯一优先任务、完成条件和续接点。
2. 从六个月目标追溯到月、周、日任务，理解今天为什么做这件事。
3. 在任务工作台内完成定位、闭卷首做、指定输入、主动加工、成果沉淀、自检和收尾。
4. 查看任务关联的知识节点、成果模板和证据要求，但不让知识地图替代计划排序。
5. 依据真实成果和证据判断进展，并让日、周、月复盘产生后续行动。
6. 在网站不可用时，仍可仅依赖仓库内 Markdown 完整继续学习。

### 2.2 非目标

V1 不包含：

- 多用户、团队协作、账号、权限角色或社交功能。
- 排行榜、积分、连续打卡、勋章等游戏化机制。
- 自动替学习者完成闭卷首版、成果或最终判断。
- 大而全的课程、资讯、收藏或内容推荐平台。
- 云同步、复杂数据库、全文知识引擎或实时协同。
- 技术栈、部署平台、模型供应商或生产依赖选择。
- 重构内容目录契约，或把生成索引升级为权威内容源。

## 3. 目标用户与核心情境

V1 只服务一个主要用户：正在执行六个月 AI Native 学习计划的仓库所有者。

| 优先级 | 情境 | 用户问题 | 成功结果 |
|---|---|---|---|
| P0 | 开始今天的学习 | 现在该做什么、为什么、做到什么算完成？ | 从唯一主任务进入正确续接步骤 |
| P0 | 执行学习会话 | 资料、动作、输出和标准如何连起来？ | 形成指定成果并完成自检 |
| P0 | 结束与续接 | 今天完成了什么，下次从哪里继续？ | 状态有证据，续接点明确 |
| P0 | 检查真实进展 | 哪些能力已有证据，哪些只是看过？ | 发现一个优先证据缺口 |
| P1 | 理解计划位置 | 今天如何服务本周、本月和六个月目标？ | 可逐级追溯目标与门禁 |
| P1 | 定位知识 | 当前任务依赖哪些节点，边界是什么？ | 找到节点及关联实践证据 |
| P1 | 周/月复盘 | 偏差来自哪里，后续如何调整？ | 形成一个有证据的调整动作 |
| P2 | 查找历史成果 | 某次判断、练习或证据在哪里？ | 通过筛选或关联找到权威文件 |

## 4. 产品原则

1. 目标优先于内容，执行优先于展示。
2. 首页由计划决定，不由最近浏览或知识树决定。
3. 一个时刻突出一个主行动，次要信息按需展开。
4. 任务完成与能力掌握分开；证据优先于手工状态。
5. 计划驱动顺序，知识地图提供上下文，两者双向可追溯。
6. AI 可以解释、质疑、出题和反馈，但不能替代首次独立版本。
7. 所有视图投影同一批对象和关系，不建立平行状态。
8. 失败、阻塞和未通过是有效运行状态，不用虚假进度掩盖。
9. 界面应降低认知负担，不用装饰性复杂度模拟“智能”。
10. Markdown 可独立使用，网站是运行层而不是数据主权层。

## 5. 核心对象与权威关系

```text
六个月目标 → 月度里程碑 → 周计划 → 每日任务
                                ↓
                        相关知识节点
                                ↓
                     学习动作 → 成果 → 证据
                                         ↓
                              日 / 周 / 月复盘
                                         ↓
                                 后续计划调整
```

| 对象 | 最小含义 | V1 关键关系 |
|---|---|---|
| Goal / Milestone | 要形成的阶段能力 | 包含计划，接受验收 |
| Task | 时间盒内完成的执行单元 | 追溯目标，关联节点、成果、证据与下一任务 |
| Knowledge Node | 概念、机制、模式或能力点 | 提供上下文，不决定执行顺序 |
| Resource | 完成任务允许使用的输入 | 受任务和开放条件约束 |
| Artifact | 学习行为形成的成果 | 由模板约束，可成为证据载体 |
| Evidence | 支持能力判断的可复查材料 | 关联任务、节点和里程碑 |
| Review | 根据结果形成的判断与调整 | 必须输出下一行动或计划变化 |
| Session | 单次学习过程与续接信息 | 记录中断点、差距和下一步 |

### 5.1 数据主权

- `content/` 下的 Markdown 是学习内容与状态的唯一权威来源。
- `00-templates/template-registry.yaml` 是成果模板的权威注册表。
- `config/learning-content.json` 定义内容边界和状态枚举。
- `web/public/data/learning-index.json` 是面向网站的生成投影，不是反向编辑源。
- 界面偏好、筛选和未提交草稿属于可丢弃临时状态，不能被解释为学习完成。
- 写回 Markdown 的机制留到技术设计阶段决定；任何方案都必须保留可审查差异、失败提示和用户最终确认。

## 6. 信息架构

### 6.1 一级导航

| 入口 | 用户问题 | 主要内容 | 默认性 |
|---|---|---|---|
| 今日 | 我现在做什么？ | 当前计划位置、唯一主任务、完成条件、续接点 | 默认入口 |
| 路线图 | 我为何做、之后做什么？ | 六个月、月、周、日层级及门禁 | 次级入口 |
| 知识地图 | 这项任务涉及什么知识？ | 知识结构、关系、能力等级、证据缺口 | 次级入口 |
| 学习档案 | 我形成过什么？ | 同一批成果与证据的多维视图 | 次级入口 |
| 复盘 | 进展真实吗，下一步如何调整？ | 偏差、证据缺口、风险和调整结果 | 次级入口 |

任务工作台和知识节点详情是上下文页面，不与五个一级入口争夺同一层级。

### 6.2 页面规格

#### PS-01 今日工作台（P0）

展示当前六个月 / 月 / 周 / 日位置、今日唯一主任务、预计时间、上层能力目标、主要成果、完成规则、证据要求、门禁状态、上次中断位置和下一动作。页面只有一个高强调主按钮：“继续当前任务”或“开始当前任务”。不得用知识总量、连续天数或大面积统计卡抢占首屏。

#### PS-02 路线图（P1）

支持从六个月阶段展开到月、周、日，明确当前项、依赖、门禁、已完成、已验证和阻塞状态。任务顺序来自计划，不由知识节点状态自动改写。过去、当前和未来可区分。

#### PS-03 任务工作台（P0）

同时提供：

1. 任务目标与上层追溯。
2. 时间盒、依赖、当前步骤和门禁。
3. 允许使用的资源及受控材料开放条件。
4. 关联知识节点及其作用。
5. 主要成果、支持成果和模板入口。
6. 完成条件、自检标准和证据要求。
7. 保存草稿、提交成果、标记阻塞和结束会话的结果反馈。

标准步骤为：定位 → 闭卷首做 → 指定输入 → 四问理解 / 主动加工 → 写入成果 → 自检 → 只修一个问题 → 收尾续接。不同任务可隐藏不适用步骤，但不得跳过计划规定的受控材料和证据规则。

#### PS-04 知识地图（P1）

展示知识层级、当前任务关联、前置 / 相关 / 后续节点、目标能力等级、当前证据和证据缺口。知识地图只负责定位；“接下来学习”必须回到计划任务。

#### PS-05 知识节点详情（P1）

回答四问：它是什么、解决什么问题、何时使用或不使用、怎样证明有效。同时显示能力等级 L0—L4 和运行状态。核心节点缺少反例、实践或证据时，明确指出差距。

#### PS-06 学习档案（P2）

以同一批 Markdown 提供成果和时间两种基础视图，并支持按月份 / 周、任务、节点、成果类型、能力等级和证据状态筛选。每条记录显示权威路径、更新时间、关联对象和状态，不复制正文形成第二份内容。

#### PS-07 复盘中心（P0/P1）

展示计划与实际偏差、能力变化、证据缺口、里程碑风险和下一调整。日复盘服务无摩擦续接，周复盘检查能力推进，月复盘按“能画、能讲、能做、能迁移、能迭代”验收。没有下一行动或计划调整时，不得显示为已完成。

## 7. 核心用户流程

### UF-01 开始并继续今日任务

```text
进入“今日” → 确认位置、任务与完成条件 → 从续接点进入任务工作台
→ 完成当前步骤 → 保存或提交成果 → 自检并记录证据
→ 写下下一续接点 → 返回今日状态
```

从打开网站到进入正确任务不超过一次主操作；用户无需先浏览知识地图。

### UF-02 受控材料学习

```text
提示闭卷规则 → 形成并保留首次版本 → 满足开放条件 → 开放参考材料
→ 只修改一个明确问题 → 差异和理由可追溯
```

### UF-03 从进展缺口回到行动

```text
复盘发现证据缺口 → 查看关联对象 → 选择计划允许的补强动作
→ 进入任务工作台 → 形成证据 → 更新后续计划或门禁判断
```

## 8. 状态与显示规则

网站使用 `config/learning-content.json` 的状态枚举，不发明另一套持久状态：`draft`、`active`、`not_started`、`learning`、`review_pending`、`completed`、`verified`、`blocked`、`archived`。

`completed` 表示当次任务满足规则，`verified` 表示已有后续独立证据，两者不得合并。知识能力采用 L0—L4：未进入、能解释、能判断、能实践、能验证与改进。运行状态和能力等级是两个维度，不得用颜色或同一标签混为一谈。

每个数据页面必须定义正常、首次 / 空、加载、部分数据、过期、错误、阻塞和只读状态。数据不完整时指出缺失字段或关系，不伪造默认值；错误时说明影响范围、保留用户草稿并提供恢复动作。

## 10. 体验与质量要求

- 核心页面不依赖英文术语才能完成任务。
- 目标为 WCAG 2.2 AA；键盘、焦点、语义结构、对比度和缩放均纳入验收。
- 桌面端适合深度学习，窄屏仍能完成 P0 流程。
- 来源、更新时间、提交结果和错误边界始终可见。
- 用户输入在导航、刷新或失败前得到保护或明确警告。
- 动效只解释状态变化，不制造注意力竞争。
- 性能目标和测量环境留到技术方案阶段；首屏必须优先呈现主任务结构。

## 11. 产品指标

核心结果指标是计划中的能力里程碑被可验证地完成。领先指标包括进入正确主任务、任务形成成果、完成任务具有证据、核心节点具有实践证据、复盘产生调整及从续接点恢复的比例。

护栏指标：无依据升级状态、受控材料提前开放、提交失败丢失草稿、网站与 Markdown 不一致且未告警的次数都应为零。

## 12. 发布边界与待决问题

“今日 → 任务工作台 → 成果 / 证据 → 日复盘 → 下一续接点”是发布阻断闭环。路线图、知识地图和档案必须服务该闭环。

以下问题留到技术设计阶段：索引读取与过期感知；Markdown 写回、冲突检测、差异预览和失败恢复；搜索、缓存和渲染方案；性能预算；部署、本地运行、浏览器矩阵和自动化测试工具。它们不得改变 Markdown 权威地位、目录 V1.0 契约和本规格定义的产品行为。

## 13. 变更规则

产品定位、目标用户、V1 范围、一级信息架构、核心对象、权威数据关系、状态、能力等级、任务闭环、证据规则或 P0 完成定义变化时，必须升级版本，并同步更新设计系统、验收标准和相关文档。
