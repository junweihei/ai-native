## 1. 验收原则

1. 以真实学习闭环是否成立为准，不以页面数量、视觉完成度或演示顺畅度替代。
2. P0 场景全部通过才可发布；P1 未通过必须有明确降级边界；P2 可按版本计划延期。
3. 正常路径、空状态、部分数据、过期、错误、只读和阻塞均属于产品。
4. 权威数据、受控材料、证据和写回失败相关问题属于发布阻断项。
5. 验收使用仓库内可追溯样例，不为演示维护第二套状态。

## 2. 当前阶段：三份文档共识门禁

本阶段不编写代码。进入原型细化或技术选型前，以下项目必须全部通过：

| ID | 验收项 | 通过标准 |
|---|---|---|
| DG-01 | 定位一致 | 三份文档均将网站定义为个人学习执行、记录、验证与复盘系统 |
| DG-02 | 范围一致 | 明确 V1 目标、非目标，并声明本阶段不选技术栈、不写网站代码 |

| DG-05 | 状态一致 | 使用配置中的状态枚举，并与 L0—L4 能力等级分离 |
| DG-06 | 架构一致 | 今日为默认入口；路线图与知识地图职责分离；任务工作台围绕任务 |
| DG-07 | 闭环完整 | 今日 → 任务 → 成果 / 证据 → 复盘 → 续接点被定义为 P0 闭环 |

## 3. 未来网站 V1 发布门禁

### 3.1 阻断级别

| 级别 | 定义 | 发布处理 |
|---|---|---|
| Blocker | 数据主权、证据、受控材料、草稿安全或核心闭环失效 | 不得发布 |
| Critical | P0 场景不可完成或无可用恢复路径 | 不得发布 |
| Major | P1 场景明显受损，但 P0 有安全替代路径 | 需明确接受并排期 |
| Minor | 不影响任务完成和正确判断的一般问题 | 可记录后发布 |

### 3.2 发布硬门禁

- AC-P0 全部通过。
- Blocker 和 Critical 缺陷为零。
- 网站状态与 Markdown 不一致且未告警为零。
- 受控材料提前开放为零。
- 写回失败导致草稿丢失为零。
- 键盘完成 P0 流程通过；关键页面对比度、缩放和窄屏通过。
- 仓库检查及未来技术栈定义的自动化测试全部通过。

## 4. P0 核心场景验收

### AC-P0-01 五秒定位今日任务

**对应需求：** FR-01、FR-02、FR-03；页面 PS-01。

给定生成索引中存在一个可执行的当前任务，当用户进入网站时：默认进入“今日”；首屏可识别当前月 / 周 / 日、唯一主任务、预计时间和上层能力目标；完成条件、主要成果、证据要求和上次续接点可在一次滚动或展开内到达；主操作明确为开始或继续当前任务；页面不以文件数、打卡天数或知识总量作为最高视觉优先级。

### AC-P0-02 计划追溯

**对应需求：** FR-02、FR-09。

从今日任务可追溯到周计划、月度里程碑和六个月目标；每一层显示名称、状态和验收关系。缺少任一关联时，界面显示“关系缺失”及受影响范围，不自动编造父级。

### AC-P0-03 从续接点恢复任务

**对应需求：** FR-03、FR-07。

给定任务存在上次会话记录，进入任务工作台后定位到已记录步骤，并显示上次时间、未解决问题和下一动作。若续接记录指向不存在的步骤，仍可进入任务概览，并提示修复关系。

### AC-P0-04 按协议完成学习会话

**对应需求：** FR-04；页面 PS-03。

任务工作台完整呈现任务目标、时间盒、依赖、当前步骤、指定资源、关联节点、主要成果、完成条件和证据。用户可以按任务配置完成定位、闭卷首做、指定输入、主动加工、成果、自检、单点修订和收尾；不适用步骤有清楚说明。

### AC-P0-05 受控材料不提前开放

**对应需求：** FR-04。

给定参考答案或闭卷后材料存在开放条件，在条件满足前，内容不可从任务工作台、常规导航、搜索预览或关联卡看到；页面解释开放条件；完成首次版本后才开放材料，并保留首次版本；参考后修订与首次版本可区分。提前泄露为 Blocker。

### AC-P0-06 成果提交与状态依据

**对应需求：** FR-05、FR-06。

提交主要成果时显示目标仓库相对路径、模板或结构要求和提交结果。仅当成果存在且完成规则通过后，任务才能进入 `completed`；进入 `verified` 还必须有后续独立证据。用户单击标签或勾选不能绕过规则。

### AC-P0-07 提交失败不丢草稿

**对应需求：** FR-06、FR-07。

模拟写回失败、冲突、权限不足和数据过期：用户输入保持可见且可复制 / 重试；页面说明失败范围、权威文件是否改变和下一步；任务状态不被提前更新；重新进入页面时有恢复路径。主要成果不可恢复丢失为 Blocker。

### AC-P0-08 任务完成与能力等级分离

**对应需求：** FR-05、FR-11。

完成一次任务后，界面可显示任务“已完成”，但相关节点只按证据支持更新到对应 L0—L4。不得因文件存在或任务完成自动显示“已掌握 / 已验证”。

### AC-P0-09 结束会话并形成续接点

**对应需求：** FR-03、FR-08。

结束会话至少记录任务 ID、成果路径、通过 / 未通过标准、一个未解决问题、能力变化证据和下一续接点。未完成任务可保持 `learning` 或转为 `blocked`，不被强制包装成完成。

### AC-P0-10 复盘产生后续行动

**对应需求：** FR-08、FR-12；页面 PS-07。

日复盘形成下一续接点；周复盘指出一个最大差距；月复盘覆盖能画、能讲、能做、能迁移、能迭代。没有具体下一行动、计划调整或“不调整及其证据”时，不能标记为完成。

### AC-P0-11 数据缺失、过期和只读

**对应需求：** FR-06、FR-07。

缺少字段时保留可用内容并标出影响；索引过期时显示生成时间、权威来源和刷新动作；只读时说明原因并解释恢复方法；加载时不先显示零进度或空档案。

### AC-P0-12 阻塞处理

**对应需求：** FR-03、FR-08。

用户可记录缺资源、数据、权限或风险等卡点。阻塞页显示已有成果、解除条件、降级路径和可继续的安全动作；不把阻塞计入完成，也不使用惩罚性文案。

## 5. P1 页面与关系验收

### AC-P1-01 路线图职责正确

路线图按六个月、月、周、日展示计划，包含当前项、依赖、门禁和状态。未来被锁定任务显示原因；路线图不根据知识树顺序自行调整计划。

### AC-P1-02 知识地图职责正确

知识地图展示知识结构、当前任务关联、前置 / 相关 / 后续节点、能力等级和证据缺口。六层、三条流、两类保障被表达为不同关系。“继续学习”回到计划任务，不另建自由进度。

### AC-P1-03 节点四问与证据缺口

节点详情可回答定义、问题、使用 / 不使用边界和验证方式。核心节点缺少反例、实践或证据时显示具体缺口；运行状态与 L0—L4 分组展示。

### AC-P1-04 双向关联

从任务可查看相关节点、成果、证据；从节点可返回相关计划任务和证据；从证据可追溯任务、节点和里程碑。断链均有可见提示。

### AC-P1-05 证据缺口回到行动

从复盘或节点发现缺口后，用户可进入计划允许的补强任务。系统不得直接把“缺少证据”变成已完成，也不得在没有计划关系时自动创建权威任务。

## 6. P2 档案验收

### AC-P2-01 同源多视图

成果视图和时间视图来自同一批 Markdown 投影。切换视图不改变状态，每条记录显示权威路径、更新时间、类型及关联关系。

### AC-P2-02 搜索与筛选

可按月 / 周、任务、节点、成果类型、能力等级和证据状态缩小结果。清空条件可恢复完整集合；无结果时说明当前筛选并提供重置动作。

### AC-P2-03 历史与归档

归档内容与活动内容可区分；归档不计入当前任务或进展。历史版本可追溯，不能被最新摘要静默替代。

## 7. 设计系统验收

| ID | 验收项 | 通过标准 |
|---|---|---|
| UI-01 | 视觉优先级 | 每页一个明确 H1 和一个主要行动；今日主任务权重最高 |
| UI-02 | 色彩语义 | 当前、已验证、警告、错误语义稳定；信息不只靠颜色表达 |
| UI-03 | 排版 | 长文本行宽、字号、行高符合设计基线，200% 缩放可读 |
| UI-04 | 组件状态 | 核心组件覆盖适用的默认、焦点、禁用、加载、空、错误、成功、只读、过期、阻塞 |
| UI-05 | 文案 | 操作使用动词 + 对象；完成、验证、掌握、阻塞含义不混用 |
| UI-06 | 反馈 | 保存 / 提交反馈说明目标、结果和状态变化；错误说明恢复办法 |
| UI-07 | 响应式 | 桌面、中宽、窄屏均保持信息顺序和 P0 流程，不遮挡输入或操作 |
| UI-08 | 动效 | 动效有功能目的，减少动态效果后无信息损失 |
| UI-09 | 数据诚实 | 加载不显示假零，部分数据不补造，图表有分母和数据时间 |
| UI-10 | 原型边界 | 冻结 V3 仅作为参考，未覆盖产品规格或内容契约 |

## 8. 可访问性验收

目标为 WCAG 2.2 AA。

### AX-01 键盘

仅用键盘完成 AC-P0-01、04、06、07、09 和 10。无键盘陷阱；焦点顺序符合任务顺序；焦点样式持续可见。

### AX-02 结构与名称

页面有唯一主标题和合理标题层级；导航、主区、辅助区和状态消息可识别；图标按钮、表单、错误和状态都有可访问名称或描述。

### AX-03 对比与非颜色信息

正文对比至少 4.5:1，大文本和关键非文本控件至少 3:1。关闭颜色感知后，运行状态、能力等级、错误和选中仍可区分。

### AX-04 缩放与重排

200% 缩放下信息和功能不丢失；320 CSS 像素等效宽度下 P0 流程无双向页面滚动。局部地图或表格若需横向滚动，不影响主操作。

### AX-05 目标与输入

主要点击 / 触控目标达到设计建议；输入有持久标签；错误可定位；未保存保护和提交反馈可被辅助技术感知。

### AX-06 动效与时间

减少动态效果后无循环或大幅位移动画。学习时间盒不构成交互超时；若未来存在会话超时，必须可延长并保护草稿。

## 9. 响应式验收矩阵

具体浏览器与设备列表留到技术设计阶段确定。

| 模式 | 代表条件 | 必验页面 | 核心标准 |
|---|---|---|---|
| 窄屏 | 320–479 CSS px | 今日、任务工作台、复盘 | 单列、操作不遮挡、可完成 P0 |
| 中宽 | 480–1023 CSS px | 任务、路线图、知识地图 | 辅助栏重排、关系仍可理解 |
| 桌面 | ≥1024 CSS px | 全部页面 | 主辅层级清楚、长文本不过宽 |
| 高缩放 | 桌面视口 200% | 今日、任务、档案 | 无内容 / 功能损失，无双向页面滚动 |

方向改变或窗口缩放后，未提交输入、当前步骤、筛选和焦点上下文不丢失。

## 10. 数据与可靠性验收

### DT-01 权威来源

抽查今日任务、一个节点、一个成果、一个证据和一个复盘，其内容、状态和关系均能追溯到 Markdown、模板注册表、内容配置或生成索引；网站不存在独立维护的永久副本。

### DT-02 状态枚举

所有持久运行状态属于 `config/learning-content.json` 允许枚举。未知状态显示为数据问题，不静默映射成“未开始”或“完成”。

### DT-03 索引时间

用户可看到数据最近生成 / 刷新时间。索引与权威内容不一致时有告警，且不得基于错误版本静默覆盖。

### DT-04 写回边界

未来写回方案必须验证目标路径在内容契约允许范围内、展示差异、处理冲突、报告结果。界面偏好和临时草稿不得改变权威状态。

### DT-05 可恢复性

刷新、前进 / 后退、窗口缩放、短暂离线或写回失败后，用户能恢复未提交内容或在离开前获得警告。恢复机制不得把草稿误记为正式成果。

## 11. 验收数据集

未来实现阶段应从已跟踪文件构造可重复样例，至少覆盖：

1. 已完成任务：M01-D01。
2. 学习中且需续接：M01-D02 或 M01-D03。
3. 未开始且有依赖：M01-D04。
4. 已有主要成果但待验收的任务。
5. 带参考答案开放条件的首测或复测任务。
6. 带闭卷原版和修订版的任务。
7. 缺少关联字段、未知状态、过期索引和无匹配档案。
8. 写回成功、冲突、权限失败和临时不可用。

验收样例只引用或从权威文件生成，不修改学习结论来配合测试。固定测试数据的组织方式留到技术阶段决定。

## 13. 验收报告模板

```text
版本 / 提交：
验收环境：
数据集版本：
通过：
失败：
未执行及原因：
Blocker / Critical：
已接受的 Major：
```
