## 1. 设计目标

设计系统要把复杂的学习运行模型转换成安静、可信、连续的个人工作台。视觉首先帮助用户判断“现在、下一步、完成条件、证据缺口”，其次才展示全局结构。

- **聚焦**：一个页面有一个主要问题和一个主行动。
- **证据感**：状态、来源、时间和判断依据清楚可查。
- **连续性**：中断、失败或跨日后仍能回到正确位置。

## 2. 设计原则

1. 先呈现行动，再呈现解释；先呈现当前，再呈现全量。
2. 用结构表达系统关系，不用卡片数量表达产品丰富度。
3. 颜色只增强含义，不单独承担状态或等级判断。
4. 同一对象在不同视图保持名称、状态、标识和动作一致。
5. “已完成”必须显得克制，“阻塞”必须显得可处理，而非奖惩化。
6. 数据缺失、过期和提交失败要诚实可见，不能用空白或默认值掩盖。
7. 深色工作台承载导航与结构，阅读和长文本区域优先保证纸面感与长时可读性。
8. 装饰、动效和英文眉题不得影响中文信息理解。

## 3. 设计语言

### 3.1 视觉方向

延续冻结 V3 原型的“深色系统工作台 + 浅色学习纸张”双表面语言：深色表面用于全局导航、系统关系、任务状态和复盘仪表；浅色表面用于长文本、四问卡、成果编辑和需要持续专注的内容。

青蓝色表示当前焦点或主操作，绿色表示已被证据支持，琥珀色表示待处理风险，红色只表示错误或高风险。不得把霓虹光效、渐变或大面积装饰当作 AI Native 的主要表达；系统感来自关系清晰和反馈可信。

### 3.2 品牌表达

- 产品名：`AI Native Learning OS`。
- 中文场景优先使用“今日、路线图、知识地图、学习档案、复盘”等直接名称。
- 英文眉题可作为次要层级，不承载唯一信息。
- V1 不以新品牌建设延迟产品闭环。

## 4. 设计令牌

令牌名称描述语义，不绑定某种样式语言或组件框架。下列值是 V1 设计基线；视觉设计可微调，但必须通过配套验收。

### 4.1 色彩

| 语义令牌 | 基准值 | 用途 |
|---|---:|---|
| `surface.canvas` | `#07101F` | 深色应用背景 |
| `surface.raised` | `#0D1A2F` | 导航、面板和结构卡 |
| `surface.subtle` | `#111F36` | 次级分组和悬停表面 |
| `surface.paper` | `#F5F7FB` | 长文本与学习纸张 |
| `border.default` | `#223553` | 深色表面边界 |
| `text.primary.dark` | `#E8F1FF` | 深色表面主文本 |
| `text.secondary.dark` | `#8EA3C4` | 深色表面辅助文本 |
| `text.primary.paper` | `#172033` | 浅色表面主文本 |
| `action.primary` | `#4EE7FF` | 当前焦点、主操作、链接 |
| `action.secondary` | `#6D8CFF` | 次级选中与结构强调 |
| `status.verified` | `#5DE3AD` | 已验证、成功反馈 |
| `status.warning` | `#FFC96B` | 待验收、过期、风险 |
| `status.danger` | `#FF7C91` | 错误、破坏性或高风险 |

规则：正文与背景对比至少 4.5:1，大号文本和非文本控件至少 3:1；标签同时包含文字或形状；主操作色不兼作“已验证”；浅色纸张需独立校验。

### 4.2 字体与排版

本阶段不选定生产字体文件。优先使用清晰的中文无衬线系统字体并提供通用回退。

| 样式 | 建议字号 / 行高 | 用途 |
|---|---|---|
| Display | 32–40 / 1.2 | 今日唯一目标、页面核心结论 |
| H1 | 28–32 / 1.25 | 页面标题 |
| H2 | 22–24 / 1.35 | 主要分区 |
| H3 | 17–18 / 1.45 | 卡片或局部分组 |
| Body | 15–16 / 1.65 | 正文和学习说明 |
| Small | 13–14 / 1.5 | 辅助信息、路径、时间 |
| Meta | 12 / 1.4 | 标签和非关键元数据 |

长文本理想行宽为 60–80 个中文字符；正文不低于 14px 等效尺寸，输入内容建议不低于 16px；状态不以全大写英文替代中文。

### 4.3 间距、圆角与层级

- 基础间距单位为 4，常用序列为 4、8、12、16、24、32、48。
- 面板内部间距：紧凑 16、标准 24、重点区域 32。
- 圆角：小控件 8、卡片 12、重点面板 16–18；同层级一致。
- 阴影只表达浮层、拖动或临时覆盖关系；普通卡片依靠边界和表面色。
- 内容密度默认舒适，档案表格可使用紧凑档。

### 4.4 动效

- 状态反馈建议 120–200ms，视图切换建议 180–280ms。
- 尊重“减少动态效果”偏好；禁用动效后不影响理解。
- 不使用自动播放、无尽脉冲或大范围背景运动。
- 保存、提交和刷新必须以文案反馈结果，不能只靠动画。

## 5. 布局系统

### 5.1 桌面

使用稳定的全局导航区和可滚动主工作区。阅读页控制行宽，地图和路线图可使用更宽画布。首屏优先放当前位置、主任务、完成条件和主操作；辅助信息放在右侧栏或折叠区。

### 5.2 中等宽度

辅助栏可折叠到主内容之后。路线图和知识地图允许横向局部浏览，但关键文字与操作不能被截断；主任务、完成规则和提交反馈保持可达。

### 5.3 窄屏

- 一级导航转为底部导航或等效模式，五个入口均可达；标签不可只剩图标。
- 单列顺序为：位置 → 主任务 → 完成标准 → 当前步骤 → 辅助信息。
- 表格转换为可读卡片，或采用带明确提示的局部横向滚动。
- 所有 P0 流程可在 320 CSS 像素等效宽度完成，无双向页面滚动。
- 固定元素不得遮挡输入、错误提示、主按钮或系统键盘区域。

## 6. 导航与页面模板

### 6.1 全局框架

包含产品标识、五个一级入口、当前页面标题、数据来源 / 更新时间和必要反馈。页面内返回动作回到用户来源上下文，而非一律回首页。

### 6.2 今日模板

信息顺序：当前计划位置 → 今日唯一结果与原因 → 继续 / 开始主操作 → 完成条件、成果和证据 → 当前步骤与续接点 → 风险和次要进展。统计数字只在帮助决策时出现。

### 6.3 任务工作台模板

- 顶部：面包屑、任务 ID、状态、时间盒、返回上下文。
- 主区：当前步骤、允许输入、成果工作区和自检。
- 辅助区：上层目标、相关节点、完成条件、证据、门禁。
- 操作区：保存草稿、提交 / 完成当前步骤、记录阻塞、结束并续接。

主操作随阶段变化，但同一时刻最多一个高强调按钮。

### 6.4 路线图模板

以层级和依赖表达计划，不以自由缩放画布为唯一用法。每个节点至少提供名称、时间范围、状态、门禁和进入详情的动作。当前路径高亮；已完成与已验证可区分；受依赖约束的任务不伪装为可立即执行。

### 6.5 知识地图模板

提供树 / 结构与详情的主从关系。选择节点时保留树中位置，当前任务关联优先可见。六层、三条流与两类保障是不同关系，不能压成同一种嵌套层级。

### 6.6 档案与复盘模板

档案以搜索、筛选、结果和权威路径为核心。复盘以差距、证据、原因和下一行动为核心。图表必须能被相邻文本完整解释。

## 7. 组件规范

### 7.1 按钮

Primary 用于页面唯一主要动作；Secondary 用于必要但不主导的动作；Ghost 用于导航、展开、筛选和低风险动作；Danger 用于可能丢失内容或改变权威文件的动作。

按钮使用动词 + 对象，如“继续当前任务”“保存草稿”“提交成果”。禁用态说明原因；加载态防止重复提交。

### 7.2 状态标签

标签由状态文字 + 可选图标组成。运行状态和能力等级使用不同形状或分组标题。`completed` 显示“已完成”，`verified` 显示“已验证”。

### 7.3 任务卡

至少含任务名称、上层位置、状态、预计时间、主要成果和下一动作。被门禁锁定时显示依赖原因。

### 7.4 完成标准与证据卡

每项显示标准、当前证据、判断状态、缺口和修正动作。手工判断必须标记为“待证据支持”，不用模糊进度条替代。

### 7.5 输入与成果区

- 字段有持久标签、说明、错误和保存状态。
- 闭卷首版与参考后修订明显分区，防止覆盖原证据。
- 自动保存不是唯一保存机制；显示最后保存时间和目标位置。
- 离开存在未保存内容的页面时提供保护。

### 7.6 提示与反馈

- 成功说明保存 / 提交到哪里以及状态是否改变。
- 警告说明继续的后果和恢复办法。
- 错误说明失败范围、未丢失内容和下一步。
- 空状态说明原因，并给一个合法动作。
- Toast 只用于短暂确认；需要决策或恢复的信息留在页面中。

### 7.7 对话框

只用于必须阻断的确认、不可逆风险或冲突。标题直接说明结果，操作使用具体动词，不使用模糊的“确定 / 取消”。

### 7.8 表格、列表与图表

表格用于精确比较，窄屏提供等价方式；列表用于任务、成果和证据序列；进度图显示可解释的分母和数据时间。禁止把文件数量、浏览次数或简单勾选包装成能力进度。

## 8. 状态设计

所有核心组件和页面在设计交付时覆盖默认、悬停、焦点、按下、禁用、加载、空、部分数据、错误、成功、只读、过期和阻塞状态。若不适用，应说明原因。

- 加载不先显示“0”。
- 部分数据保留可用关系并标出缺口。
- 过期数据显示生成时间和刷新动作。
- 写回失败保留草稿，不提前更新为完成。
- 阻塞态描述事实和解除条件，不责备用户。

## 9. 内容设计

语气清晰、克制、可行动，像可靠的学习教练。避免营销口号、拟人化催促、焦虑性倒计时和空泛鼓励。

- 使用仓库既有术语：任务、知识节点、成果、证据、门禁、复盘、续接点。
- “完成”只描述任务规则满足；“验证”只描述后续独立证据。
- “掌握”必须伴随 L0—L4 定义或具体证据。
- 路径显示可读名称；需要追溯时同时显示任务 ID 或仓库相对路径。

| 不使用 | 使用 |
|---|---|
| 确定 | 提交成果 |
| 下一步 | 进入闭卷首做 |
| 同步成功 | 已写入 `content/...`，状态仍为待验收 |
| 出错了 | 提交失败；草稿已保留，可重试或复制内容 |
| 100% 掌握 | 该节点已达到 L2，仍缺实践证据 |

## 10. 可访问性基线

- 所有功能可仅用键盘完成，焦点顺序符合视觉与任务顺序。
- 焦点指示清楚、持续可见，不能被装饰或固定区域遮挡。
- 图标按钮有可访问名称；状态变化有等价文本。
- 标题层级、地标、列表、表格和表单关系语义清楚。
- 错误同时在字段附近和摘要位置可定位，不只用颜色表达。
- 200% 缩放下无信息或功能损失；文本重排不造成双向页面滚动。
- 点击 / 触控目标建议至少 44 × 44 CSS 像素，紧凑数据区最低不小于 24 × 24 且有足够间距。
- 键盘快捷操作有等价界面操作，不抢占常用按键。

## 11. 设计交付清单

进入开发前，设计交付至少包含：

- 五个一级入口和两个上下文页面的页面结构。
- P0 流程从开始、执行、提交、复盘到续接的完整串联。
- 桌面、中等宽度和窄屏三类布局。
- 核心组件及第 8 节规定的适用状态。
- 键盘焦点、错误恢复、未保存保护和受控材料开放说明。
- 示例数据注明来源，缺失数据不由设计稿虚构。
- 与产品需求 ID、验收场景 ID 的可追踪标注。

设计评审以 P0 闭环是否清楚、关键状态是否可处理、产品语义是否一致判定，不以页面数量或视觉精细度判定。
